02多 Agent 协作产品

技术方案

PM Agent 调度多 Agent，串联需求分析、设计、开发、测试与交付过程。

角色AI 应用产品项目经理阶段产品机制验证与迭代方向多 Agent 编排 / 任务协同
01 业务场景02 Agent 分工03 状态观测04 结果校验05 当前问题06 复盘反思

01业务场景

个人开发者和小型项目团队在 AI 辅助交付时，经常遇到需求拆解、上下文管理、任务状态跟踪和结果复核成本高的问题。

  • 任务拆解粒度不稳定，执行结果难追踪
  • 多个 Agent 职责边界不清晰，容易重复或遗漏
  • 缺少执行过程观测与失败样本沉淀

02Agent 分工

Planner理解需求，拆解任务，制定执行计划与依赖关系。
Research Agent检索信息、提炼要点，形成结构化资料。
Review Agent审核内容准确性、完整性与表达质量。

03状态观测

用户任务提交需求
Planner任务拆解
Agent执行反馈
事件流SSE 观测
输出校验确认交付

04结果校验

内容质量

要点覆盖、逻辑连贯、表达清晰。

结构规范

格式统一、章节完整、引用合规。

合规检查

敏感内容识别，引用来源有效性检查。

05当前问题

任务拆解粒度

部分任务拆解粒度不足，导致执行效果不稳定。

领域知识覆盖

特定领域检索覆盖不全，影响资料质量。

人工介入时机

复杂任务中人工确认节点仍需进一步优化。

06复盘反思

先明确交付物

明确目标交付物与验收标准，再反推子任务。

失败样本很重要

沉淀失败案例，分析原因，反哺 Agent 流程优化。
